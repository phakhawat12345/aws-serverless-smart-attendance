บทที่ 1: บทนำ

1.1 ความเป็นมาและความสำคัญของปัญหา

ในบริบทของการเรียนการสอนในระดับอุดมศึกษา กระบวนการบันทึกการเข้าเรียนของนักศึกษา (Attendance Tracking) เป็นขั้นตอนที่มีความสำคัญในการวัดผลและเช็กพฤติกรรมการเข้าเรียน อย่างไรก็ตาม วิธีการเช็กชื่อแบบดั้งเดิม ไม่ว่าจะเป็นการขานชื่อทีละบุคคล หรือการส่งกระดาษเวียนเซ็นชื่อ ต่างประสบปัญหาหลักหลายประการ ได้แก่:

  1. การเสียเวลาเรียน (Time Inefficiency): การเช็กชื่อแบบขานชื่อในห้องเรียนที่มีนักศึกษาจำนวนมาก (เช่น 50–100 คนขึ้นไป) เสียเวลาการเรียนการสอนไปโดยเฉลี่ย 10–15 นาทีต่อคาบ
  2. ปัญหาการเช็กชื่อแทนกัน (Attendance Fraud): การเซ็นชื่อในกระดาษเปิดโอกาสให้นักศึกษาทำการเซ็นชื่อแทนเพื่อนที่ไม่ได้มาเรียนจริง
  3. ความยากในการสรุปและจัดการข้อมูล (Data Collection Overhead): ผู้สอนต้องนำข้อมูลจากกระดาษมาคีย์ลงระบบบันทึกคะแนนด้วยตนเองอีกครั้ง ซึ่งเสี่ยงต่อความผิดพลาดและเสียเวลาประมวลผล

เพื่อแก้ไขปัญหาข้างต้น การนำเทคโนโลยีคลาวด์คอมพิวติ้ง (Cloud Computing) เข้ามาประยุกต์ใช้ร่วมกับระบบ Dynamic QR Code จึงเป็นทางออกที่มีประสิทธิภาพ โดยระบบ Smart Attendance ถูกออกแบบให้อยู่บนสถาปัตยกรรมแบบไร้เซิร์ฟเวอร์ (Serverless Architecture) ของ Amazon Web Services (AWS) ซึ่งรองรับการประมวลผลแบบยืดหยุ่น (Scalability) ต้นทุนต่ำ (Cost-Effective) และทำงานแบบเรียลไทม์ (Real-time Processing) โดยไม่จำเป็นต้องบริหารจัดการโครงสร้างพื้นฐานเซิร์ฟเวอร์ด้วยตนเอง

1.2 วัตถุประสงค์

  1. เพื่อออกแบบและพัฒนาระบบเช็กชื่อเข้าเรียนอัจฉริยะที่ใช้รหัส PIN ประจำคาบเรียน (Classroom PIN Verification) ร่วมกับการสแกน QR Code เพื่อป้องกันการเช็กชื่อแทนกันและประมวลผลได้อย่างรวดเร็ว
  2. เพื่อประยุกต์ใช้บริการคลาวด์ AWS ในรูปแบบ Serverless จำนวน 4 บริการหลัก ได้แก่ Amazon S3, Amazon API Gateway, AWS Lambda และ Amazon DynamoDB
  3. เพื่อพัฒนาระบบที่มีสถาปัตยกรรมแบบ Serverless ที่รองรับผู้ใช้งานพร้อมกันจำนวนมากและทำงานอยู่ในเกณฑ์ AWS Free Tier
  4. เพื่อจัดทำเอกสารคู่มือการติดตั้งและการใช้งาน (Documentation) ที่มีความละเอียดและชัดเจนจนทำให้กลุ่มอื่นสามารถทำตามได้สำเร็จ

1.3 ขอบเขตของการศึกษา

     1. ขอบเขตด้านฟังก์ชันการทำงาน

  • ส่วนสำหรับผู้สอน
  • สร้างรอบการเช็กชื่อ (Session) เพื่อแสดงผล Dynamic QR Code หน้าห้องเรียนพร้อมตั้งเวลาหมดอายุ (Expiration Time)
  • เรียกดูรายงานสรุปประวัติการเข้าเรียนของนักศึกษาในแต่ละรายวิชาได้แบบเรียลไทม์
  • ส่วนสำหรับนักศึกษา
  • ล็อกอินเข้าใช้งานระบบผ่านอุปกรณ์เคลื่อนที่ (Smartphones / Tablets)
  • สแกน QR Code หน้าห้องเรียนเพื่อส่งคำขอเช็กชื่อเข้าเรียน
  • ระบบแสดงผลและแจ้งเตือนสถานะการเช็กชื่อแบบเรียลไทม์ (Real-time Feedback) ทันทีบนหน้าจอ (เช่น "เช็กชื่อสำเร็จ", "QR Code หมดอายุ")
  • ระบบบันทึกเวลาเข้าเรียน (Timestamp) และสถานะการเข้าเรียน (PRESENT / LATE) อัตโนมัติ อัตโนมัติลง Amazon DynamoDB
  • เรียกดูประวัติและสรุปสถิติการเข้าเรียนย้อนหลังของตนเอง (Student Attendance History Dashboard) แยกตามรายวิชาและวันเวลาที่เข้าเรียนได้ตลอดเวลา

     2. ขอบเขตด้านเทคโนโลยีและบริการ AWS

  • ส่วนจัดเก็บและโฮสติ้ง (Storage & Hosting): Amazon S3 (Static Website Hosting)
  • ส่วนเชื่อมต่อโปรแกรม (API Gateway): Amazon API Gateway (REST API)
  • ส่วนประมวลผล (Compute): AWS Lambda (Python 3.12 Runtime)
  • ส่วนฐานข้อมูล (Database): Amazon DynamoDB (NoSQL Database)

บทที่ 2: เอกสารและงานวิจัยที่เกี่ยวข้อง

2.1 แนวคิดเกี่ยวกับ Cloud Computing และ Serverless Architecture

คลาวด์คอมพิวติ้งแบบ Serverless ไม่ได้หมายความว่าไม่มีเซิร์ฟเวอร์อยู่จริง แต่เป็นรูปแบบที่ผู้พัฒนาไม่จำเป็นต้องคอยบริหารจัดการ Provision, Scale หรือ Maintain เซิร์ฟเวอร์เอง โดย AWS จะเป็นผู้รับผิดชอบโครงสร้างพื้นฐานทั้งหมด ระบบจะคิดค่าบริการตามการใช้งานจริง (Pay-as-you-go) และหยุดคิดค่าบริการเมื่อไม่มี Request เข้ามา

2.2 ทฤษฎีและบริการ AWS ที่ประยุกต์ใช้

  1. Amazon Cognito: บริการจัดการยืนยันตัวตน (Authentication) และกำหนดสิทธิ์ (Authorization) รองรับ User Pools สำหรับสร้างระบบ Signup/Signin สอดคล้องกับมาตรฐาน OAuth 2.0 และ JWT (JSON Web Tokens)
  2. Amazon S3 (Simple Storage Service): บริการจัดเก็บวัตถุ (Object Storage) ที่มีความทนทานสูง ในโปรเจกต์นี้ใช้ฟีเจอร์ Static Website Hosting เพื่อให้บริการหน้าเว็บ HTML/JS ฝั่งผู้ใช้งาน
  3. Amazon API Gateway: บริการสร้าง เผยแพร่ และดูแลรักษา RESTful API ซึ่งทำหน้าที่เป็นประตูด่านหน้าเชื่อมต่อคำขอจาก Client ไปยัง AWS Lambda
  4. AWS Lambda: บริการประมวลผลแบบ Event-Driven Serverless Compute ทำหน้าที่รันโค้ด Python เมื่อได้รับ Trigger จาก API Gateway
  5. Amazon DynamoDB: ฐานข้อมูล NoSQL แบบ Fully Managed ให้ค่า Latency ในระดับ Millisecond รองรับโครงสร้างข้อมูลแบบ Key-Value เหมาะกับการเก็บ Log และ Session ที่มี Read/Write สูง

2.3 งานวิจัยและระบบที่เกี่ยวข้อง

จากการศึกษาระบบเช็กชื่อด้วย QR Code ทั่วไปพบว่า ปัญหาสำคัญคือ "การถ่ายภาพ QR Code ส่งต่อให้เพื่อนสแกนแทน" การวิเคราะห์แนวทางแก้ไขจึงนำมาสู่การใช้ Dynamic QR Code ที่ผูกกับ SessionID และมี Expiration Time ร่วมกับการยืนยันตัวตนผ่าน Amazon Cognito ซึ่งช่วยป้องกันการเช็กชื่อแทนกันได้อย่างมีประสิทธิภาพ

ขั้นตอนการลบทรัพยากรบน AWS ตามลำดับ (แนะนำให้ลบย้อนหลังจากหน้าเว็บไปหลังบ้าน)

1.ลบ Amazon S3 Bucket (Frontend)

  1. ไปที่บริการ Amazon S3
  2. คลิกเลือก Bucket ของหน้าเว็บคุณ (เช่น smart-attendance-frontend-...)
  3. สำคัญ: ก่อนลบ Bucket คุณต้องลบไฟล์ (Objects) ข้างในทั้งหมดก่อน โดยคลิกเข้าไป > เลือกไฟล์ทั้งหมด > กด Delete > พิมพ์คำว่า permanently delete เพื่อยืนยันการลบไฟล์
  4. เมื่อ Bucket ว่างแล้ว ให้กลับมาที่หน้าหลักของ S3 เลือก Bucket นั้นอีกครั้ง แล้วกดปุ่ม Delete bucket > พิมพ์ชื่อ Bucket เพื่อยืนยันการลบ

2.ลบ Amazon API Gateway (Backend API)

  1. ไปที่บริการ API Gateway
  2. คลิกเลือก API ของคุณ (เช่น AttendanceAPI)
  3. มองหาปุ่ม Actions ด้านบน หรือเมนูการตั้งค่า แล้วคลิก Delete API
  4. พิมพ์ชื่อ API เพื่อยืนยันการลบทิ้ง

3.ลบ AWS Lambda Function

  1. ไปที่บริการ AWS Lambda > คลิกเลือก Functions
  2. เลือกฟังก์ชันของคุณ (เช่น CheckInStudent)
  3. ที่มุมขวาบน ให้คลิกเมนู Actions > เลือก Delete
  4. พิมพ์ชื่อฟังก์ชันเพื่อยืนยันการลบ

4. ลบตาราง Amazon DynamoDB

  1. ไปที่บริการ Amazon DynamoDB > เมนูด้านซ้ายเลือก Tables
  2. เลือกตารางของคุณ (AttendanceLogs)
  3. คลิกปุ่ม Delete ด้านบน
  4. ติ๊กยืนยันการลบ CloudWatch alarms (ถ้ามี) แล้วพิมพ์คำว่า delete เพื่อลบตารางฐานข้อมูลทิ้ง

5. ลบ Amazon Cognito User Pool

  1. ไปที่หน้าคอนโซลของบริการ Amazon Cognito แล้วเลือกเมนู User pools
  2. คลิกเลือก User Pool ของโปรเจกต์คุณ (เช่น User pool - bc6s-4 หรือ SmartAttendanceUserPool)
  3. ไปที่เมนูการตั้งค่าหรือเลื่อนหาปุ่ม Delete user pool บริเวณด้านบนสุด เพื่อยืนยันการลบทิ้งและเคลียร์ทรัพยากรทั้งหมด

บทที่ 4: ผลการศึกษาและผลการวิเคราะห์ข้อมูล

4.1 ผลการทดสอบการทำงานของระบบ

ผลการทดสอบระบบ Smart Attendance แบ่งออกเป็น 3 ส่วนหลัก:

  1. ผลการยืนยันตัวตน (Cognito Authentication): ผู้ใช้งาน (อาจารย์/นักศึกษา) สามารถสมัครสมาชิกและเข้าสู่ระบบได้ถูกต้อง ป้องกันผู้ไม่ได้รับอนุญาตเข้าถึงหน้าเช็กชื่อ
  2. ผลการสแกนเช็กชื่อ (API & Lambda Processing): เมื่อนักศึกษาสแกน QR Code หน้าเว็บจะยิง POST Request ผ่าน API Gateway ไปยัง Lambda ซึ่งสามารถประมวลผลคำขอเสร็จสิ้นภายในเวลาเฉลี่ย 1–2 วินาที
  3. ผลการบันทึกข้อมูล (DynamoDB Storage): ข้อมูลประวัติการเช็กชื่อถูกบันทึกลงตาราง AttendanceLogs อย่างแม่นยำ พร้อมระบุเวลา Timestamp ตรงตามจริง

4.2 ผลการประเมินประสิทธิภาพและต้นทุน

  • ความเร็วและการรองรับผู้ใช้งาน (Latency & Scalability): โครงสร้างแบบ Serverless ทำให้ระบบรองรับการยิง Request พร้อมกันของนักศึกษาทั้งห้องเรียนได้โดยไม่เกิดอาการระบบล่ม (Server Crash)
  • ค่าใช้จ่าย (Cost Management): จากการทดสอบระบบตามขอบเขตโปรเจกต์ ปริมาณการเรียกใช้ API Gateway, Lambda Executions และ DynamoDB Reads/Writes ทั้งหมดอยู่ภายใต้ AWS Free Tier ทำให้ไม่มีค่าใช้จ่ายเกิดขึ้นจริง

บทที่ 5: สรุป อภิปรายผล และข้อเสนอแนะ

5.1 สรุปผลการดำเนินงาน

การพัฒนาระบบ Smart Attendance ประสบความสำเร็จตามวัตถุประสงค์ที่ตั้งไว้ ระบบสามารถทำงานได้ครบถ้วนผ่าน 4 บริการหลักบน AWS (Amazon S3, Amazon API Gateway, AWS Lambda และ Amazon DynamoDB) ช่วยแก้ไขปัญหาการเช็กชื่อแบบดั้งเดิม ลดเวลาการเช็กชื่อในห้องเรียนเหลือเพียงไม่กี่วินาที เพิ่มความแม่นยำในการจัดเก็บข้อมูลลงในฐานข้อมูล และมีการเพิ่มกลไกการตรวจสอบรหัส PIN หน้าห้องเรียน (Classroom PIN Verification) ผ่านฟังก์ชัน AWS Lambda เพื่อควบคุมการเช็กชื่อให้อยู่ภายในพื้นที่ห้องเรียนได้อย่างมีประสิทธิภาพ  

5.2 อภิปรายผล

สถาปัตยกรรมแบบ Serverless มีข้อดีอย่างเด่นชัดในเรื่องการไม่ต้องดูแลเซิร์ฟเวอร์ และมีความยืดหยุ่นสูง อย่างไรก็ตาม จากการทดสอบพบข้อสังเกตเกี่ยวกับ Cold Start ของ AWS Lambda ในการเรียกใช้งานครั้งแรกสุด ซึ่งอาจใช้เวลาตอบสนองช้ากว่าปกติเล็กน้อย (ประมาณ 1–2 วินาที) แต่ในการเรียกใช้งานครั้งถัดไป (Warm State) ระบบสามารถตอบสนองได้อย่างรวดเร็ว

5.3 ข้อเสนอแนะ

  1. การพัฒนาระบบสุ่มรหัส PIN อัตโนมัติ (Dynamic PIN Generator): แม้ระบบปัจจุบันจะมีกลไกตรวจสอบรหัส PIN ประจำคาบเรียนแล้ว แต่ในอนาคตควรพัฒนาต่อยอดให้มีหน้าจอควบคุมฝั่งผู้สอน (Teacher Dashboard) สำหรับสุ่มรหัส PIN แบบอัตโนมัติทุกๆ 1 หรือ 2 นาที เพื่อป้องกันปัญหาการแอบถ่ายรูปหรือส่งต่อรหัส PIN จากระยะไกลให้รัดกุมยิ่งขึ้น
  2. การยืนยันตัวตนขั้นสูง (Advanced Authentication / Geolocation): สามารถพัฒนาต่อยอดโดยการเพิ่มระบบตรวจสอบพิกัดตำแหน่งทางภูมิศาสตร์ (GPS Geolocation) หรือการเชื่อมต่อระบบยืนยันตัวตนผ่านบัญชีอีเมลของสถาบันการศึกษา (Email Authentication / SSO) เพื่อยืนยันตัวตนผู้เรียนได้อย่างแม่นยำ 100%
  3. การแจ้งเตือนอัตโนมัติ (Automated Notification): สามารถต่อยอดโดยเชื่อมต่อกับ Amazon SNS เพื่อส่งข้อความแจ้งเตือนสรุปรายชื่อนักศึกษาที่ขาดเรียนไปยังอีเมลของอาจารย์ผู้สอนแบบอัตโนมัติหลังหมดรอบเช็กชื่อ
